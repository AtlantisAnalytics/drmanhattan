# `wmk recover` and crash testing: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the catalog from `wmk.toml` and `packs/` alone, naming any damage, and prove with crash tests that a killed ingest never costs the repository.

**Architecture:** A new `recover` module scans every pack with a new salvage scanner (resyncs past damage), hashes every unit into a fresh catalog in `tmp/`, replays each snapshot record through a new streaming reader, recomputes image dimensions, marks damaged snapshots, checks the result, and swaps it in atomically while keeping the old catalog. Supporting changes: format version 2 with a `damaged` snapshot status, a missing-catalog guard and tmp sweep in ingest, content-completeness checks in ingest/restore/verify, and kill-point failpoints driven from the CLI binary.

**Tech Stack:** Rust (rust-toolchain 1.99.1, MSRV 1.87), rusqlite (bundled SQLite), blake3, ciborium, fail 0.5, clap, assert_cmd.

**Spec:** `docs/superpowers/specs/2026-11-25-recover-design.md`

## Global Constraints

- Run cargo as `PATH="$HOME/.cargo/bin:$PATH" cargo ...` (Homebrew's old cargo shadows rustup).
- Gate for every task: `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test --all-features`.
- Packs are never written by recover. The old catalog is never deleted.
- Memory is bounded independently of repository size: the snapshot record is streamed; hashing holds at most a few units per worker (units ≤ 16 MiB).
- Speed: recover within roughly 1.5x of a full `verify` on the same repository.
- Recover accepts any pack ids, duplicate units across packs, and snapshots from different hosts, and never assumes one ingest history.
- Public repository: no host names, user names or personal paths in committed files or tests.
- Exit codes: 0 success, 1 error, 2 damage / verification failure, 3 entries withheld by screening.
- Do not bump crate versions; the release (0.3.0) is a separate step.
- Commit messages end with the session's `Co-Authored-By` / `Claude-Session` trailer lines. Write messages to a file and use `git commit -F` (heredocs can hang here).

## Review Focus

1. **A snapshot containing empty files** (content with `unit_count = 0`): must recover as intact, never `damaged`. Test in Task 7.
2. **Recover run twice in a row (same second):** both old catalogs are kept under distinct names, second run exits 0. Test in Task 8.
3. **A repository with no packs at all:** recover succeeds with an empty catalog and exits 0. Test in Task 8.
4. **An unreadable pack file (permission denied):** an I/O error, not damage: exit 1, catalog untouched. Test in Task 8.
5. **A snapshot record spanning many chunks** (thousands of entries): replay streams it and matches the original rows. Test in Task 6.

### Task 5: Salvage scanner

**Files:**
- Modify: `crates/core/src/pack.rs` (new function; `scan` unchanged for its callers)
- Test: unit tests in `crates/core/src/pack.rs` (they need `encode_record_header` to craft records with valid CRCs)

**Interfaces:**
- Produces:
```rust
pub struct Salvage {
    /// From the file header; None if the header is unreadable (file skipped).
    pub id: Option<Id>,
    /// (offset, header) of every record whose header validates, in offset order.
    pub records: Vec<(u64, RecordHeader)>,
    /// Consistent end-anchored footer whose BLAKE3 matches the bytes before it.
    pub sealed_blake3: Option<Hash32>,
    /// End of the last valid record (the pack row's size when not sealed).
    pub valid_end: u64,
    /// Human-readable problems: bad magic/format, id/name mismatch,
    /// damaged ranges, unsupported kinds, failing index entries, footer mismatch.
    pub problems: Vec<String>,
}
pub fn salvage(path: &Path) -> Result<Salvage>; // Err only for I/O errors
```
- Algorithm: parse sequentially from offset 26; on an invalid or unsupported record at `pos`, record a problem and search forward from `pos + 1` for the marker bytes `52 4B 4D 57`, trying `parse_record_at` at each hit, until the data end (the footer offset when a consistent footer exists, else file length). Unsupported kind/compression with a valid CRC: problem, resume searching at `pos + RECORD_HEADER_LEN`. Footer index entries not matching a found record are problems. The file-name check compares the header id with the `<id>.pack` stem.

- Produces:
```rust
pub struct RecoverOptions { pub workers: usize } // 0 = one per CPU; Default
pub struct DamagedSnapshot { pub id: Id, pub files: Vec<Vec<u8>> } // sorted paths
pub struct LostRecord { pub unit: Hash32, pub snapshot: Option<Id>, pub why: String }
pub struct RecoverReport {
    pub packs: u64, pub units: u64, pub bytes_read: u64,
    pub snapshots: Vec<Id>,            // recovered, in id order (damaged included)
    pub damaged: Vec<DamagedSnapshot>,
    pub lost: Vec<LostRecord>,
    pub warnings: Vec<String>,         // problems that cost no file
    pub not_recovered: Vec<Id>,        // filled by Task 8
    pub old_catalog: Option<PathBuf>,  // filled by Task 8
    pub elapsed_ms: u64,
}
impl RecoverReport { pub fn intact(&self) -> bool } // damaged and lost both empty
/// Build a complete, checked catalog at `dest` (must not exist) from the
/// packs. Does not touch catalog.sqlite or wmk.toml.
pub fn build(repo: &Repo, dest: &Path, opts: &RecoverOptions) -> Result<RecoverReport>;
```
- Order inside `build`:
  1. `salvage` every pack (parallel over files, `workers` threads); for each record read the payload, decompress, BLAKE3; keep the first intact copy of each hash, warn on corrupt copies and on corrupt units with no intact copy (these become damage only if referenced). Insert `pack` rows (sealed iff `sealed_blake3` is `Some`; `size` = file length if sealed, else `valid_end`) and `unit` rows, in batched transactions. Feed pack problems into `warnings`.
  2. For each `snapshot_record` unit: one transaction with `PRAGMA defer_foreign_keys = ON`; insert items as `stream_record` yields them (contents: the `content` row plus `content_unit` rows only for units present); commit only on `Ok`, else roll back and push a `LostRecord`. Same snapshot id from two different record units → both rolled back / not inserted, one `LostRecord` each. Snapshot row = header with `record_unit = Some(unit)`.
  3. Media: for every content with `format` in jpeg/png/webp/gif/avif and complete leading units, read its first `SNIFF_LEN` bytes and insert `media(width, height)` via `image_dims`.
  4. Damage: for each snapshot, `incomplete_contents`; if non-empty set `status = 'damaged'` and list the file paths.
  5. Check: `PRAGMA integrity_check` = ok, `PRAGMA foreign_key_check` empty, and `manifest_snapshot(cat, id, b"", {mtime_precision_ns: 1, cross_fs: false}).core == manifest_hash` for every recovered snapshot; any failure → `Err`.
  6. `PRAGMA wal_checkpoint(TRUNCATE)` and close.

  - `ingest::kill::after_walk` — `pipeline`, right after `walk_source` returns.
  - `ingest::kill::before_sync` — `Storage::barrier`, before `p.writer.sync()`.
  - `ingest::kill::after_sync` — `Storage::barrier`, after `sync()`, before sending ops.
  - `catalog::kill::after_commit` — catalog writer, right after a transaction commits.
  - `ingest::kill::during_record` — in `seal_snapshot`'s record unit callback, after sending a unit.
  - `ingest::kill::record_durable` — end of `seal_snapshot`, after the final `flush`.
  - `ingest::kill::before_upsert` — `finish`, before the final durable upsert (the last pack is sealed by then).
  - `ingest::kill::after_upsert` — `finish`, after the final durable upsert.
